## What the migration has to handle

Hand-written from the probe run; each item names the matrix rows it comes from. "All FTP" means vsftpd, ProFTPD and Pure-FTPd, plain and FTPS, except the `ftps-proftpd-tls13` column, which fails for its own reason (item 20). "S3" means both servers unless one is named; Garage fails every `copy`/`move` with default options because it lacks object ACLs (item 8), so `s3-rustfs` is the column to read for S3 copy and move semantics. Neither S3 server is AWS: behaviour on real AWS S3 is not verified here.

### Overwrite and "target exists"

1. `write` and `writeStream` replace an existing file silently, without exception, on local, S3 and all FTP (`write.existing`, `writeStream.existing`).
2. `move` onto an existing file replaces it silently on local, RustFS and all FTP; the source is gone afterwards (`move.onto-file`).
3. `copy` onto an existing file replaces it silently on local, RustFS, ProFTPD and Pure-FTPd; on vsftpd and Garage it fails before anything is written (items 8 and 19), and with `['retain_visibility' => false]` it replaces silently on every backend (`copy.onto-file`, `copy.without-retain-visibility`).
4. A target that is a directory is refused on local and all FTP (`write`, `move` and `copy` onto a directory throw, nothing changes), but accepted on S3: the object `d` is created next to the prefix `d/`, so a file and a directory of the same name coexist and list as `f:d d:d` (`write.onto-directory`, `move.onto-directory` and `copy.onto-directory` on RustFS, `mkdir.onto-file`).
5. Writing below a path whose parent is a file throws on local and all FTP and succeeds on S3, which then holds `f.txt` and `f.txt/child.txt` (`write.below-file`).
6. `move`/`copy` of a file onto itself return without error and leave the file intact everywhere except `copy` on vsftpd (`move.onto-itself`, `copy.onto-itself`); Flysystem's default `ResolveIdenticalPathConflict::TRY` hands the call to the adapter, and the S3 adapter returns early.
7. A cheap exists check exists on every adapter: on S3 `fileExists` is 1 `HeadObject`, `directoryExists` is 1 `ListObjectsV2` (`MaxKeys` 1), and `has` is 1 request for an existing file and 2 (`HeadObject` + `ListObjectsV2`) for a directory or a missing path; on FTP `fileExists` is `SIZE` and `directoryExists` is `CWD`, on local a `stat` (`s3req.fileExists`, `s3req.fileExists-missing`, `s3req.has-file`, `s3req.has-dir`, `s3req.has-missing`, `s3req.directoryExists`). A check-then-act sequence is not atomic on any backend.

### S3

8. Flysystem's S3 `copy` (and therefore `move`) first calls `visibility()` = `GetObjectAcl` on the source unless `retain_visibility` is false or a `visibility` is passed; a server without ACL support (Garage answers `NotImplemented`, HTTP 501) then fails every copy and move, and on RustFS a copy costs `GetObjectAcl, HeadObject, CopyObject` = 3 requests and a move 4 (plus `DeleteObject`), versus 2 for a copy with `retain_visibility => false` (`s3req.copy`, `s3req.move`, `s3req.copy-no-retain`, `copy.*` on `s3-garage`).
9. `fileSize()` then `readStream()` is exactly one `HeadObject` plus one `GetObject` on S3; `fileSize()` of a missing file is one `HeadObject` and throws `UnableToRetrieveMetadata` (`s3req.fileSize+readStream`, `s3req.fileSize-missing`). `mimeType` and `lastModified` are one `HeadObject` each, `write`/`writeStream`/`createDirectory` one `PutObject`, `delete` one `DeleteObject`, and a listing of a small directory one `ListObjectsV2`, shallow or deep (`s3req.*`).
10. `createDirectory` writes a zero-byte marker object `dir/`, for nested paths only the deepest one (`a/b/c/`, no markers for `a/` and `a/b/`); `write` into missing directories creates no markers (`mkdir.new`, `mkdir.nested`, `write.missing-parents`, raw keys).
11. `directoryExists` is true for explicit (marker) and implicit (only a file below) directories, but an implicit directory disappears when its last file is deleted, while an explicit one stays (`exists.dir-implicit`, `s3.empty-directory-lifecycle`).
12. A deep S3 listing returns directory entries only for marker objects: implicit directories (and the intermediate levels of `createDirectory('a/b/c')`) are missing, while a shallow listing does return implicit directories (from `CommonPrefixes`) with `last_modified` null (`list.dir.deep`, `list.dir.shallow`, `mkdir.nested`, `write.missing-parents`). Code that builds a tree from a deep listing has to derive directories from file paths.
13. `move` or `copy` of a directory fails on S3 (there is no object at the directory key), so renaming a folder has to be implemented as list, copy each object, delete each object; on local and all FTP `move` of a directory is a native rename, and `copy` of a directory fails everywhere (`move.directory-source`, `copy.directory-source`, `rename-directory`).
14. `deleteDirectory` on S3 deletes by key prefix (`ListObjects` + `DeleteObjects` = 2 requests for 3 entries), removes implicit directories as well, does not touch the sibling `d-other/` or the file `d.txt`, and returns without error for a missing directory and for a file path (the file stays) (`s3req.deleteDirectory`, `deleteDirectory.*`).
15. On a component with an S3 `prefix`, `fileExists('')` is true when the prefix itself has a marker object (`exists.root`, `exists.root-empty`); on local and FTP the root is only a directory.

### Listings

16. A listing entry is a `FileAttributes`/`DirectoryAttributes` object whose `path` is relative to the filesystem root without leading or trailing slash, whatever form (`dir`, `/dir`, `dir/`) was listed, on every backend (`list.path-form`, `list.root.*`); the one exception is ProFTPD, where listing a path that is a file yields one file entry with the absolute path plus a trailing slash (`/.../f.txt/`), while all others return an empty listing (`list.file`).
17. File entries carry `type`, `path`, `file_size`, `visibility`, `last_modified`, `mime_type` (always null in listings) and `extra_metadata` (S3: `ETag`, `StorageClass`, else empty); directory entries carry `type`, `path`, `visibility`, `last_modified`, `extra_metadata`; on S3 `visibility` is null for all entries and `last_modified` null for directories, on FTP `last_modified` is null unless `timestampsOnUnixListingsEnabled` is true, local and FTP derive `visibility` from permission bits; compared to Flysystem 1, `basename`, `dirname` and `extension` are gone and have to be derived from `path`, `size` is now `file_size` and `timestamp` is now `last_modified` (`list.dir.shallow`, `list.dir.deep`).
18. Listing order differs: local is unsorted (directory order), FTP is sorted by name, an S3 shallow listing returns directories first and then files, an S3 deep listing is sorted by key; a missing path gives an empty listing without exception everywhere (`list.dir.*`, `list.missing`).

### FTP

19. `visibility()` on FTP uses `STAT <path>`, and vsftpd answers `STAT dir/name` only if a file `name` also exists in the current directory (the adapter's root), so `visibility()` of a file below the root throws `UnableToRetrieveMetadata` on vsftpd, and so does every default `copy` there because it calls `visibility()` first; ProFTPD and Pure-FTPd answer correctly (`visibility.same-basename`, `meta.file`, `copy.to-missing`). Minimal reproduction with plain ext-ftp against vsftpd 3.0.5: after `ftp_chdir($c, '/vt')`, `ftp_raw($c, 'STAT /vt/sub/x.txt')` returns `["213-Status follows:", "213 End of status"]` (no entry) until a file `/vt/x.txt` exists; then it returns the entry of `/vt/sub/x.txt`.
20. FTPS works on vsftpd, ProFTPD with TLS 1.2 and Pure-FTPd; with ProFTPD's default of requiring TLS session reuse on data connections and TLS 1.3 enabled, PHP's ext-ftp reuses the session only for the first data connection of a control connection, and every later transfer fails with `Unable to build data connection: Operation not permitted` (server log: `client did not reuse TLS session, rejecting data connection`), which breaks every read after a write and every listing after the first (column `ftps-proftpd-tls13`; server-side fix: `TLSProtocol TLSv1.2` or `TLSOptions NoSessionReuseRequired`).
21. `lastModified()` uses `MDTM` and works on all three daemons with second precision; listings carry `last_modified` only with `timestampsOnUnixListingsEnabled` (minute precision, year guessed from the `ls` date format) and null otherwise (`list.ftp-timestamps`). All three daemons answer `SYST` with `UNIX Type: L8`, for which the adapter drops the `-aln` list options and sends a plain `LIST` (seen in manual ext-ftp tests, not a matrix row); the `ls`-style lines of the three daemons differ in column widths and in numeric versus named owners, which the adapter's whitespace split handles, so files and directories list identically on all three (`list.dir.*`).
22. Failed uploads on FTP raise a PHP warning that the adapter does not silence (`ftp_fput(): ...`, followed by `UnableToWriteFile`); in a Yii application the error handler turns that warning into `yii\base\ErrorException` before `UnableToWriteFile` is thrown, so the facade must catch it as well or suppress warnings around FTP calls (`write.onto-directory`, `path.long-300`, `copy.onto-directory` on ProFTPD).
23. `deleteDirectory` of a missing directory or of a file throws `UnableToDeleteDirectory` on all FTP, while local and S3 return without error (`deleteDirectory.missing`, `deleteDirectory.file`); `delete()` of a directory throws on local and returns without error and without effect on S3 and all FTP (`delete.directory`); `createDirectory` where a file of that name exists throws on local, vsftpd and Pure-FTPd and returns without error and without effect on ProFTPD (`mkdir.onto-file`).
24. A control connection that died is detected with `NOOP` before the next call and reopened transparently (`ftp.reconnect`); a wrong password or a missing root fails on the first filesystem call, not when the component is built (`ftp.connect-wrong-password`, `ftp.missing-root`).
25. `mimeType()` on FTP downloads the whole file to sniff it (`FtpAdapter` is built with `detectMimeTypeUsingPath = false`, which creocoder does not expose); this comes from the adapter source, the probe does not count FTP transfers.

### Local adapter

26. `readStream()`/`read()` of a directory return an empty stream/string with an unsilenced warning instead of throwing, so stream and download must check the path first, for example with `fileSize()`, which throws for a directory; `lastModified()` of a directory works (`readStream.directory`, `meta.directory`).
27. With creocoder's default `linkHandling` (`DISALLOW_LINKS`) a single symlink anywhere in the listed tree makes the whole `listContents` throw `SymbolicLinkEncountered`, and `SKIP_LINKS` leaves links out silently (`local.symlinks.default`, `local.symlinks.skip`).
28. In both link modes direct access follows links (`fileExists`, `read`, `fileSize`, and `write` through a directory link), `delete()` of a file link removes only the link, and `deleteDirectory()` of a directory link deletes the contents of the link target and then throws, also when the target lies OUTSIDE the root (`local.symlinks.*`, `local.symlink-outside-root`).
29. creocoder's `LocalFilesystem` defaults create files with 0644 and directories, including implicitly created parents, with 0740 (`defaultForDirectories` private), so other users and container processes cannot enter new directories; listings report these directories as `private` (`local.permissions`, `list.dir.shallow`).

### Mime types and paths

30. `mimeType()` sniffs the content first and uses the extension only when the content is inconclusive: PNG bytes named `image.txt` give `image/png`, text named `fake.png` gives `image/png`, an empty `empty.txt` gives `text/plain`; for a text file or an empty file without extension local and FTP throw `UnableToRetrieveMetadata`, while S3 returns the `Content-Type` stored at upload, `application/octet-stream` (`mime.*`).
31. Paths are normalised identically on all adapters by Flysystem: leading, trailing and double slashes, `.` and inner `..` segments, and backslashes (turned into `/`, so a name cannot contain a backslash); `..` above the root throws `PathTraversalDetected`, NUL, control characters and newlines throw `CorruptedPathDetected`; spaces, `#`, `%`, `+`, `?`, `[`, `]`, `*` and umlauts in NFC and NFD are stored and listed byte-identically everywhere; a 300-byte name fails on local, all FTP and RustFS and works on Garage (`path.*`).

### Bugs and gaps found

32. `creocoder/yii2-flysystem` 2.0.0-beta1.1: the FTP component works with the phd5 config (the constructor fix is effective), and no further bug was hit; gaps are that `AwsS3Filesystem` exposes neither the S3 client nor adapter options (`options`, `streamReads`), so the probe counts requests through a subclass that reads the client back from the adapter by reflection (`./probe/src/CountingAwsS3Filesystem.php`), that `FtpFilesystem` does not expose `detectMimeTypeUsingPath` (item 25), and that `LocalFilesystem` defaults directories to 0740 (item 29).
33. `league/flysystem-ftp` 3.36.0: `visibility()`, and with it every default `copy`, depends on `STAT` output that vsftpd does not give for files below the current directory (item 19), and `ftp_fput` warnings are not silenced (item 22); `league/flysystem-local` 3.35.3: `deleteDirectory()` follows directory symlinks, also out of the root (item 28).
34. Test-stack findings, not adapter behaviour: Alpine's Pure-FTPd package is built `--with-minimal` and answers `NOOP`, `STAT` and `FEAT` with `500 Unknown command`, which made the adapter reconnect before every call (a failed `NOOP` counts as a dead connection), so the stack compiles Pure-FTPd from source; vsftpd 3.0.5 on Alpine in standalone mode (`listen=YES`) died with SIGSEGV after FTPS sessions and runs under `tcpsvd` instead.
